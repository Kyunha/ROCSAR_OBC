Overview

System Architecture

Monostatic SAR system running on a Ettus B210 (B200 variant) connected via USB 3.0 to a DietPi/aarch64 host. TX and RX run in parallel threads, both locked to a shared USRP time reference.

params.json ──▶ config.hpp ──▶ connect.cpp (main)
│
signal.cpp ──▶ tx_thread ──▶ B210 DAC
│ t_start shared
rx_thread ◀── B210 ADC ──▶ rx_data_TIMESTAMP.bin
│
ATR GPIO FP0 pin0 ── TX envelope

Module

Signal Generation — LFM Chirp

A linear frequency-modulated (LFM) chirp is generated at startup as a std::vector<std::complex<int16_t>>. Samples are scaled to INT16_MAX for sc16 OTW format.

Why LFM? LFM chirps give SAR systems large time-bandwidth product — long pulse duration (energy) with wide bandwidth (range resolution). The matched filter (pulse compression) collapses the chirp to a sharp range peak.
libs/signal/signal.cpp 
static constexpr double SAMPLE_RATE    = 10e6;
static constexpr double PULSE_DURATION = 10e-6;  // 10 µs
static constexpr double BW             = 5e6;    // 5 MHz bandwidth
static constexpr double F0             = -BW / 2;

const std::vector<std::complex<int16_t>> SIGNAL_TX = []()
{
    const size_t N = static_cast<size_t>(SAMPLE_RATE * PULSE_DURATION);
    std::vector<std::complex<int16_t>> sig(N);
    const double k = BW / PULSE_DURATION; // chirp rate

    for (size_t i = 0; i < N; ++i) {
        double t     = i / SAMPLE_RATE;
        double phase = 2.0 * M_PI * (F0 * t + 0.5 * k * t * t);
        sig[i] = std::complex<int16_t>(
            static_cast<int16_t>(std::cos(phase) * 32767),
            static_cast<int16_t>(std::sin(phase) * 32767)
        );
    }
    return sig;
}();

Module

TX Thread

Each pulse is explicitly time-stamped using md.time_spec. The next pulse time is computed by incrementing t_next by the PRI — this is deterministic and immune to thread scheduling jitter.

libs/tx/tx_thread.hpp — signature 
void tx_thread_func(
    uhd::usrp::multi_usrp::sptr  usrp,
    double                       prf,
    double                       session_dur,
    double                       fs,
    uhd::time_spec_t             t_start,   // shared with RX
    std::atomic<bool>&           stop_flag
)
libs/tx/tx_thread.hpp — pulse loop 
for (size_t pulse = 0; pulse < total_pulses && !stop_flag; ++pulse)
{
    md.time_spec      = t_next;
    md.start_of_burst = (pulse == 0);
    md.end_of_burst   = (pulse == total_pulses - 1);

    const size_t sent = tx_stream->send(
        SIGNAL_TX.data(),
        SIGNAL_TX.size(),
        md,
        2.0   // timeout [s]
    );

    t_next += uhd::time_spec_t(pri); // deterministic, no jitter
    md.start_of_burst = false;
    md.has_time_spec  = true;
}
Explicit timestamps per pulse Every pulse carries its own time_spec. The USRP holds samples in its FIFO and releases them at exactly the right clock tick — not when the CPU delivers them.
sc16 OTW format SIGNAL_TX is int16_t scaled to ±32767. Travelling over USB as sc16 halves bandwidth vs fc32. The B210 DAC receives native 12-bit values — UHD truncates the bottom 4 bits.
Watch for [U] underruns If you see [U] in the terminal the CPU is not feeding samples fast enough. Lower PRF or reduce FS temporarily to diagnose.

Module

RX Thread

The full session buffer is allocated upfront. No file I/O occurs during capture — writing happens only after all pulses are received. This prevents disk latency from causing overflows.

libs/rx/rx_thread.hpp — buffer allocation 
const size_t window_samps = static_cast<size_t>(window_dur * fs);
const size_t total_pulses  = static_cast<size_t>(session_dur * prf);
const size_t total_samps   = total_pulses * window_samps;

// Allocate entire session upfront — fail early if OOM
std::vector<std::complex<int16_t>> buffer;
try {
    buffer.resize(total_samps);
} catch (const std::bad_alloc& e) {
    throw std::runtime_error("[RX] Not enough memory: "
                             + std::string(e.what()));
}
libs/rx/rx_thread.hpp — receive loop 
for (size_t pulse = 0; pulse < total_pulses && !stop_flag; ++pulse)
{
    // RX window = TX pulse time + t_min
    uhd::time_spec_t t_pulse = t_start + uhd::time_spec_t(pulse * pri);
    uhd::time_spec_t t_rx    = t_pulse + uhd::time_spec_t(t_min_s);

    uhd::stream_cmd_t cmd(uhd::stream_cmd_t::STREAM_MODE_NUM_SAMPS_AND_DONE);
    cmd.num_samps  = window_samps;
    cmd.stream_now = false;
    cmd.time_spec  = t_rx;
    rx_stream->issue_stream_cmd(cmd);

    // Write directly into the session buffer at the right offset
    std::complex<int16_t>* pulse_ptr = buffer.data() + pulse * window_samps;
    // ... recv() loop into pulse_ptr ...
}
libs/rx/rx_thread.hpp — file write (post-capture)
// All pulses captured — now write std::string filename = std::string("rx_data_") + timestamp + ".bin"; std::ofstream outfile(filename, std::ios::binary | std::ios::trunc); outfile.write( reinterpret_cast<const char*>(buffer.data()), pulses_recvd * window_samps * sizeof(std::complex<int16_t>) ); // Layout: [pulse0][pulse1]...[pulseN] // Each pulse = window_samps × complex<int16_t>
Buffer size estimate At default params: 2750 pulses/s × 25s × 900 samples × 4 bytes = ~247 MB. Verify DietPi has enough free RAM before running full session.

Module

GPIO — ATR Hardware Mode

FP0 pin 0 is driven by the B210 FPGA ATR (Automatic Transmit/Receive) state machine. The pin goes HIGH sample-accurately when a TX burst starts — no software jitter.

connect.cpp — GPIO setup 
// pin 0 = ATR controlled, output
usrp->set_gpio_attr("FP0", "CTRL",   0x0001, 0x0001);
usrp->set_gpio_attr("FP0", "DDR",    0x0001, 0x0001);
usrp->set_gpio_attr("FP0", "ATR_TX", 0x0001, 0x0001); // HIGH during TX
usrp->set_gpio_attr("FP0", "ATR_0X", 0x0000, 0x0001); // LOW when idle
ATR state machine
Idle ──▶ ATR_0X → pin LOW
TX burst ──▶ ATR_TX → pin HIGH ✓
RX only ──▶ ATR_RX → pin LOW (default)

TX / RX Synchronisation

t_start is computed once in connect.cpp after zeroing the USRP clock, then passed by reference to both threads. Both threads index pulse n from the same origin.

connect.cpp — shared time reference 
// Zero the USRP hardware clock
usrp->set_time_now(uhd::time_spec_t(0.0));

// Single t_start — both threads use this
uhd::time_spec_t t_start = usrp->get_time_now()
                           + uhd::time_spec_t(cfg.start_offset_s);

// TX: t_pulse[n] = t_start + n × PRI
// RX: t_rx[n]    = t_start + n × PRI + t_min_s
Result RX window for pulse n is always t_min_us–t_max_us microseconds after the nth TX pulse, regardless of OS scheduling, thread wake-up latency, or USB transfer timing.

Data Validation — Python

validate.py 
import numpy as np
import matplotlib.pyplot as plt

# Match your params.json values
PRF          = 2750.0
FS           = 10e6
SESSION_DUR  = 25.0
T_MIN_US     = 10.0
T_MAX_US     = 100.0

total_pulses = int(PRF * SESSION_DUR)
window_samps = int((T_MAX_US - T_MIN_US) * 1e-6 * FS)

# sc16 = interleaved int16 I/Q
raw  = np.fromfile("rx_data_TIMESTAMP.bin", dtype=np.int16)
IQ   = raw[0::2] + 1j * raw[1::2]
data = IQ.reshape(total_pulses, window_samps)

# Range-time intensity image
plt.figure(figsize=(12, 6))
plt.imshow(np.abs(data), aspect='auto', origin='lower',
           extent=[T_MIN_US, T_MAX_US, 0, SESSION_DUR])
plt.colorbar(label='Amplitude')
plt.xlabel('Range time [µs]')
plt.ylabel('Slow time [s]')
plt.title('Range-Time Intensity')
plt.tight_layout()
plt.show()
